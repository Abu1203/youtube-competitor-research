# YouTube 竞品视频挖掘

基于 Python / Tkinter 的桌面工具，按品牌搜索 YouTube 公开视频，维护本地历史台账，并导出 Excel。网页模式用 yt-dlp 搜索、优先使用 ytscrape 获取详情，也可选择 YouTube Data API。

## 功能

- 配置多个品牌、官方频道及补充搜索词，排除官方频道内容。
- 在搜索到的视频中，标题或完整描述任一包含品牌或配置词即可入选；描述命中只是线索，不表示已确认赞助或视频画面中一定出现品牌。
- 按 2024 年至当前年份筛选（至少显示到 2026 年），补扫历史红人频道的视频、Shorts 和直播。
- 相关度与最新发布两种排序发现线索，先持久化，再轮流处理各品牌详情。
- 断点续接、失败隔离、限额暂停；界面可查看每个品牌的排除原因和待处理数量。
- 按视频 ID 去重、复用详情缓存，保留批次指标快照。
- 查询历史台账，删除和恢复记录，手动修改地区及类型。
- 导出第一列为品牌，按品牌分组，后接原有 11 列：视频内容、视频链接、发布时间、观看量、点赞量、评论量、频道名称、网红频道链接、粉丝数、地区、类型。同一视频关联多个品牌时分别列出。

搜索结果和合作提示词只提供研究线索，不代表已经确认商业合作。公开搜索也不能保证发现全部相关视频。

## 安装与启动

需要 Python 3.10+（含 Tcl/Tk）以及可访问 YouTube 的网络。Windows 是主要使用环境；macOS / Linux 需要可用的图形桌面和 Tkinter。

Windows 首次使用：

1. 安装 Python，勾选 Add Python to PATH，保留 Tcl/Tk 组件。
2. 下载并解压本仓库，双击 `安装或更新采集依赖.bat`。
3. 安装完成后双击 `启动竞品红人挖掘.bat`。

也可以使用独立虚拟环境：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python "竞品红人视频挖掘.py"
```

macOS / Linux 激活虚拟环境后，执行 `python -m pip install -r requirements.txt` 和 `python 竞品红人视频挖掘.py`。部分 Linux 发行版需另行安装 Tkinter。

## 基本用法

首次启动品牌框为空，请填写自己的品牌名。官方账号可选，支持 `@账号`、`/@账号`、`/channel/UC…` 和 `/user/…`；补充搜索词使用逗号分隔。

选择年份，点击“开始 / 继续采集”。默认每词、每种排序最多读取 300 条线索，当次最多请求 500 条视频详情；搜索深度和详情额度都可调整到 10,000。每个搜索词还会追加所选年份形成扩展查询，最终按详情日期筛选。线索先保存，发现阶段结束后按品牌轮流补详情。搜索结果可能重叠或提前耗尽，上限不代表一定返回相同数量。

相同品牌、年份、深度、刷新选项和模式再次开始，会自动继续最近未完成批次；只提高详情额度也可续接。完成的查询跳过，失败或中断查询重新分页并按视频 ID 去重，已处理线索不再消耗详情额度。这里的恢复粒度是查询和视频，网页模式不保存 YouTube 内部翻页令牌。更改搜索设置会建立新批次，并继续复用历史详情缓存。

“查看采集进度”区分去重线索、按品牌入库、待处理、详情失败、缺少日期、官方频道、年份不符、手动删除等数量。达到本次额度会显示“可继续”，不会假装全部完成。官方频道填写错误只影响对应品牌；未填官方账号时无法排除该品牌官方视频。

只有勾选“刷新历史指标”才重新读取已有指标。地区和缺失互动指标不再阻塞批量采集，可在“历史台账”点击“补齐历史缺失字段”。缺日期的视频保留重试。遇到限流或验证时停止并保留队列，稍后再试。

官方 API 模式按品牌和季度轮流分页，保存下一页位置与未完成查询；每页完成后保存进度。详情仍按官方批量接口读取，地区等额外网页补齐同样后置。API 令牌若失效，可更改搜索深度建立新批次。

“一键导出当次 Excel”可在采集中途使用；“历史台账”支持按品牌、年份、关键词、批次筛选和导出。更多操作见 [使用说明](使用说明.txt)。

## 数据与隐私

开源版不附带真实品牌配置、采集数据、历史台账、工作簿或第三方依赖目录。首次运行在项目目录创建 `竞品视频台账.sqlite3`；导出保存在 `导出文件/`。运行目录需要可写，请自行备份台账。

这些本地文件已加入 `.gitignore`，请勿强制提交。旧版 `竞品红人挖掘_工作数据.json` 如存在，会被自动导入本地台账。

官方 API 模式需要你自己的 API Key，界面输入使用遮罩且不写入台账。请求会发送至 Google / YouTube；网页采集请求会发送至 YouTube。日志、截图和导出文件分享前仍应人工检查。

Excel 导出使用代码内置的空白样式，无需业务模板。可在本地放置 `竞品youtube视频数据.xlsx` 自定义样式，模板首行仍使用原有 11 列；导出时自动在最左侧添加品牌列。该工作簿默认被忽略。

## 已知限制

- 线索数量不等于相关视频或确认合作数量，不能承诺每个品牌都有几千、几万条有效记录。
- “完成”表示当前设置下的任务已处理，并不代表抓取了全站全部结果。频道补扫上限分别应用于视频、Shorts、直播三个标签页。
- 网页结构、访问验证和接口配额可能影响采集，缺失指标与明确为 0 的指标分别处理。
- 地区来自频道公开信息，未公开或读取失败会明确标注。
- 观看量、粉丝数等是采集时的公开值，不是视频发布当年的值；网页日期按 UTC 处理。
- 类型由规则推断，可以人工修改。请按平台规则和适用的数据使用要求开展研究。

## 开源经验与实现选择

参考 [scrapetube](https://github.com/dermasmid/scrapetube) 的轻量视频发现、排序和频道分页方式，保留已使用的 yt-dlp 作为采集引擎，采用其支持的搜索 URL 排序过滤。没有引入第二套爬虫运行依赖，也没有复制第三方实现。

详情处理借鉴任务队列的持久化与失败隔离思路，用现有 SQLite 保存任务，避免桌面工具额外依赖 Redis/Celery。API 按 [官方 search.list 文档](https://developers.google.com/youtube/v3/docs/search/list) 使用下一页令牌；没有把单次搜索上限当成全站总量。设计与恢复边界见 [变更说明](CHANGELOG.md)。
